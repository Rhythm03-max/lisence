# Plan: Mauritius Business Licensing Platform (NELS clone)

## 1. Goal

Build a website replicating `business.edbmauritius.org` (National Electronic Licensing
System, Mauritius): a public business-licensing portal with permit search + verification,
an applicant self-service portal, and an admin panel — backed by **Supabase**.

### Decisions locked in
- **Stack:** Next.js (App Router, TypeScript) + Tailwind CSS + Supabase
- **Scope:** Full portal **+ permit application workflow**
- **Accounts:** Admin (email/password, roles) + applicant self-service (register, profile,
  apply, track status)
- **Branding:** Replicate Mauritius government branding exactly

### Reference analysis (what was inspected)
The live portal is currently in maintenance mode, so the analysis combined the
WebSphere portal's server-rendered HTML, the searchable cache of its pages, and the
fully live mirror `business.edlbmauritius.org` (same product, static + Supabase).

Key finding: **the reference itself runs on Supabase** — auth (email/password + email OTP),
Postgres RPCs, a `candidate-photos` storage bucket, and RLS. Its client surface:

- RPCs: `search_public_permit(p_permit_number, p_issued_date, p_holder)`,
  `verify_candidate(p_token)`, `admin_create_candidate`, `admin_update_candidate`,
  `admin_list_candidates`, `admin_archive_candidate`, `admin_rotate_verification_token`,
  `admin_set_candidate_photo`
- Tables: `admin_profiles(user_id, role, is_active)` + candidate/permit records
- Exported client API: `signIn`, `signOut`, `registerByEmail`, `requireAdmin`,
  `createCandidate`, `updateCandidate`, `listCandidates`, `deleteCandidate`,
  `rotateToken`, `verifyCandidate`, `searchPermit`, `getPhotoUrl`, `makeQrPng`,
  `makeQrSvg`, `verificationUrl`
- Verification tokens match `/^v1_[A-Za-z0-9_-]{43}$/`, rotated (revoking the old link),
  and drive a QR code pointing at `verify.html?token=…`

## 4. Database schema (Supabase / Postgres)

**Tables**

| Table | Purpose / key columns |
|---|---|
| `profiles` | 1:1 `auth.users`. `role` ('admin'\|'officer'\|'applicant'), `is_active`, title, first/last name, gender, email, mobile, nationality, passport_number, date_of_birth, address |
| `agencies` | name, slug, description, logo_path (e.g. Ministry of Labour, EDB, Fire Service…) |
| `permit_categories` | name, slug (Construction, Education, Environment, Health, Manufacturing, Safety, Schemes, Study & Live, Tourism, Work & Live) |
| `permits` | name, slug, `category_id`, `agency_id`, description, `legislation_links jsonb`, `steps jsonb`, `required_documents jsonb`, fee, `is_active` |
| `permit_records` | **publicly searchable issued permits**. `permit_number` (unique), `permit_id` (type), `status` ('active'\|'pending'\|'expired'\|'cancelled'), `authority`, surname, first_name, nationality, gender, passport_number, date_of_birth, employer, post_held, `issued_date`, `valid_from`, `valid_to`, `conditions text[]`, `photo_path`, `verification_token` (unique), `archived`, `created_by` |
| `applications` | `applicant_id`, `permit_id`, `status` ('draft'\|'submitted'\|'under_review'\|'more_info_required'\|'approved'\|'rejected'), `form_data jsonb`, `reviewer_id`, `reviewer_notes`, `issued_record_id`, timestamps |
| `application_documents` | `application_id`, `document_type`, `file_path`, `uploaded_at` |
| `news` | title, slug, body, `category` ('morcellement'\|'event'), `published_at`, `is_active` |
| `faqs` | question, answer, `type` ('faq'\|'did_you_know'\|'notice'), `sort_order`, `is_active` |

**Permit number format:** `MOL-WP-2026-23794` — generated server-side from agency
prefix + type + year + sequence (Postgres function, race-safe).

**RPCs (`SECURITY DEFINER`, role-checked inside):**
- Public: `search_public_permit(p_permit_number, p_issued_date, p_holder)` (returns the
  public card fields only; never exposes DB ids), `verify_permit_by_token(p_token)`
- Applicant: `get_my_applications()`, `submit_application(p_permit_id, p_form_data)`,
  `cancel_application(p_id)`
- Admin: `admin_list_permit_records`, `admin_create_permit_record`,
  `admin_update_permit_record`, `admin_archive_permit_record`,
  `admin_rotate_verification_token`, `admin_list_applications`,
  `admin_review_application(p_id, p_decision, p_notes)`,
  `admin_list_profiles`, `admin_set_profile_role`, `admin_toggle_profile_active`

**Storage buckets (private):**
- `permit-photos` — read via short-lived signed URLs (1 h), uploaded under
  `{record_id}/{uuid}.{ext}` (jpeg/png/webp, ≤5 MB)
- `application-documents` — applicant uploads, admin reads via signed URLs

**RLS:** enabled on every table. Admin access = `EXISTS(profiles WHERE user_id = auth.uid()
AND role IN ('admin','officer') AND is_active)`; public reads limited to published
news/faqs/permits/agencies and RPC-driven public search.

## 5. Public pages & functionality

1. **Home `/`** — "Welcome to the National Electronic Licensing System of Mauritius"
   hero with mountain graphic, **Apply for Permit** button, licensing search box
   (jumps to search-permits), Port Louis banner photo, 4 quick cards
   (Agencies → licensing?view=agency, Permits → licensing, News, Notices).
2. **Licensing `/licensing`** — tabs **Category | Agency** (synced to `?view=agency`),
   accordion groups, each permit row: name + legislation link(s) + `APPLY` button.
3. **Permit detail `/licensing/[slug]`** — from the original portal's permit pages:
   title, "Steps for this permit" numbered workflow, required-documents checklist
   (two-column list with markers), legislation info links, `APPLY` CTA → wizard.
4. **Search Permits `/search-permits`** — form: Permit Number (required), Issued Date,
   Permit Holder. Normalizes government print formats (`WPNO:MOL-WP-…` prefix strip).
   Renders the public permit card: authority header, permit number, status badge,
   holder identity + photo, employer/post, passport/DOB, gender, issue date, validity
   range, numbered conditions list; smooth-scroll to result; empty/error states.
5. **Verify `/verify/[token]`** — validates `^v1_[A-Za-z0-9_-]{43}$`, loads record,
   renders the same permit card; `noindex,nofollow`, loading → not-found states.
6. **News `/news`** — Morcellement Board panel + News & Events list with
   First/Prev/page/Next/Last pagination.
7. **FAQ's & Notices `/faq`** — three tabs: FAQs, Did You Know, Notices;
   helpdesk mailto CTA.
8. **Terms / Privacy** — static content pages.

## 6. Auth flows

- **Register `/register`** — Title, First/Last name, Gender, Email, Mobile →
  `signInWithOtp` (email link) → **Account Activation** page explains next steps →
  on first sign-in, profile row created via trigger and the profile wizard runs.
- **Login `/login`** — email + password; show/hide password; redirect by role
  (`admin|officer` → `/admin`, `applicant` → `/dashboard`); `?next=` deep-link support
  with same-origin path validation.
- **Forgot / reset password** — Supabase `resetPasswordForEmail` → `/reset-password`
  (updatePassword flow).
- **Middleware** refreshes the session cookie; guards `/admin` (role), `/dashboard`,
  `/apply`, `/applications/*` (authenticated) and redirects signed-in users away from
  `/login`.
- Sign-out everywhere clears cookies and returns to `/`.

## 7. Applicant self-service portal

- **Dashboard `/dashboard`** — greeting, "Start new application", cards for each
  application with status chip + progress timeline (Submitted → Under review →
  Approved/Rejected), quick links to browse permits.
- **Apply wizard `/apply/[permitSlug]`** — multi-step form (progress bar, draft saved
  to `applications.form_data`):
  1. Applicant/profile details (prefilled, editable)
  2. Permit-specific fields (dynamic fields per permit type)
  3. Document upload (per `required_documents`, drag & drop → `application-documents`)
  4. Review + declaration → `submit_application`
- **Application detail `/applications/[id]`** — full status timeline, submitted
  documents, reviewer notes, downloadable permit (on approval: link to the public
  `/verify/[token]` record), "request more info" responses.
- **Profile `/profile`** — edit personal details, change password, mobile verification.

## 8. Admin panel (`/admin`, sidebar shell)

Sidebar: Overview · Permit Records · Applications · Users · News & Notices ·
Public Permit Search · Return to Website; topbar with admin email + Sign out.

1. **Overview** — stat cards (total records, active, expiring soon, pending
  applications, applicants) + recent activity table.
2. **Permit Records** — form-based create/edit matching the reference exactly:
   - Fieldsets: Permit info (number, status select, issuing authority), Personal
     (surname, first name, nationality, gender, passport, DOB), Employment & validity
     (employer, post held, issue date, validity from/to), Photo upload, Conditions
     (one per line)
   - **Live permit preview** panel rendering the exact public card as you type
   - **QR panel**: generates print-ready QR (1200 px PNG + SVG download) linking to
     `/verify/{token}`; "Rotate QR" with confirm → old link revoked
   - **Records table**: avatar + name, permit number, employer, issue/validity, status
     chip, client-side search, row actions (QR · Edit · Archive with confirm)
3. **Applications** — review queue: filter by status, open an application → view
   applicant profile, form answers, document previews (signed URLs), then
   Approve / Reject / Request more info with notes. **Approve** mints the
   `permit_records` row (auto permit number + verification token) and shows the QR.
4. **Users** — list `profiles` with role, status, last sign-in; change role,
   activate/deactivate, view applicant's applications.
5. **News & Notices / FAQs** — CRUD for `news` and `faqs` rows (title, type, body,
   publish date, active toggle).

## 9. Security checklist

- RLS on all tables; every privileged path goes through role-checked RPCs
- `@supabase/ssr` only — anon key in client, **service-role key never shipped** (only
  used server-side if needed, env-only)
- Route protection in middleware + re-check in server components
- Zod validation on all forms (client + server actions / route handlers)
- Private storage + signed URLs (1 h) for photos and application documents
- Verification tokens: crypto-random `v1_` 43-char, unique index, rotation revokes old
  link; verify page `noindex` + `no-referrer`
- File upload limits (≤5 MB, jpeg/png/webp), server-side type check
- Rate-limit public search/verify route handlers

## 11. Verification

- `npm run lint` + `npm run build` clean
- Supabase local (`supabase start`) → migrations + seed apply without error
- Manual E2E script:
  1. Public: home → licensing (both tabs, accordions) → permit detail → search a seeded
     record by number/date/holder (incl. `WPNO:` prefix case) → verify via QR token →
     invalid-token not-found path
  2. Applicant: register → activation → login → apply wizard (upload docs) → submit →
     track status → profile edit
  3. Admin: login → create record with photo → live preview matches card → download
     QR (PNG/SVG) → rotate token (old link dies) → table search/edit/archive →
     review application → approve (permit number + QR issued) → users role change →
     news/FAQ CRUD
  4. Security: applicant hits `/admin` → denied; anon `select` on `permit_records`
     blocked by RLS; photo URL not accessible without signed URL

## 12. Assumptions

- Seed data mirrors the reference catalog (categories, agencies, permits, steps,
  document checklists) and demo users; real content is managed by the admin afterward.
- Deployment target is Vercel (or any Node host) + hosted Supabase; env vars documented.
- SMS/OTP for mobile is out of scope (email verification only), matching the mirror.
